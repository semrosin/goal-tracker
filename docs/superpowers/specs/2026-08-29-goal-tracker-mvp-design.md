# Goal Tracker — дизайн MVP

**Дата:** 2026-08-29
**Статус:** согласовано для ревью перед планированием реализации

## Цель

Создать русскоязычный адаптивный одностраничный трекер накоплений. Пользователь ведёт локальные финансовые цели, записывает пополнения и снятия и сразу видит текущую сумму и прогресс к цели.

## Границы MVP

В MVP входят:

- создание, редактирование и удаление целей;
- добавление и удаление операций пополнения и снятия;
- обзор всех целей и отдельная страница цели;
- локальное хранение только в `localStorage`;
- адаптивная вёрстка для мобильных и больших экранов;
- Redux Toolkit, React Router, TypeScript, SCSS и Feature-Sliced Design.

Не входят backend, аккаунты, авторизация, синхронизация, сроки целей, мультивалютность и редактирование отдельных операций.

## Продуктовые решения

- Новая цель всегда начинается с баланса `0 ₽`; форма создания не принимает стартовую сумму.
- Целевые суммы и суммы операций принимаются только как положительные целые рубли.
- Все денежные значения форматируются в российских рублях, интерфейс полностью на русском языке.
- Карточка обзора содержит только название, процент, прогресс-бар и строку «накоплено / цель».
- Удаление цели или операции всегда требует подтверждения.

## Маршруты и пользовательские сценарии

### `/` — обзор целей

На странице отображается заголовок, кнопка «Новая цель» и сетка карточек. При отсутствии целей пользователь видит пустое состояние с той же кнопкой. Кнопка открывает модальное окно с полями названия и целевой суммы. Нажатие на карточку открывает страницу соответствующей цели.

### `/goals/:id` — детали цели

Страница содержит кнопку возврата к обзору, текущий баланс, прогресс, редактирование и удаление цели. Ниже располагается форма операции с переключателем «Пополнить / Снять», полем суммы и кнопкой сохранения. История операций выводится от новых к старым, с типом, суммой, датой и действием удаления. Неизвестный идентификатор показывает состояние «Цель не найдена» и безопасный путь назад.

На мобильных экранах блоки выстраиваются вертикально, основные действия занимают удобную ширину, а интерактивные элементы остаются достаточно крупными для касания.

## Данные и инварианты

```ts
type Goal = {
  id: string;
  title: string;
  targetAmount: number;
  createdAt: string;
};

type Transaction = {
  id: string;
  goalId: string;
  type: 'deposit' | 'withdrawal';
  amount: number;
  createdAt: string;
};
```

Redux хранит только массивы `goals` и `transactions`. Баланс не сохраняется отдельным полем: он выводится из журнала как сумма пополнений минус сумма снятий. Прогресс — `min(100, balance / targetAmount * 100)`; селектор дополнительно не допускает отрицательного результата.

Каждая операция проверяется в момент изменения состояния:

- название цели обязательно;
- целевая сумма и сумма операции — конечные положительные целые числа;
- снятие допускается только в пределах текущего вычисленного баланса;
- баланс не может стать отрицательным;
- удаление цели каскадно удаляет все её операции.

## Архитектура

```text
app/       store, typed hooks, providers, router, global SCSS
pages/     overview page, goal detail page
widgets/   goals list, goal detail sections
features/  goal CRUD, transaction add/delete, forms, confirmations
entities/  goal and transaction types, selectors, small UI
shared/    localStorage adapter, formatters, ID/date helpers, common UI
```

Верхние FSD-слои зависят только от нижних. Страницы не вычисляют баланс и прогресс: они получают готовые данные селекторами. Для MVP используются простые типизированные массивы сущностей, без Entity Adapter; это делает модель прозрачной и достаточной для локального небольшого набора данных.

Store имеет две доменные ветви: `goals` и `transactions`. `app` предоставляет типы `RootState` и `AppDispatch`, а также типизированные хуки. Маршрутизация строится через React Router; к store подключается `react-redux`.

## Хранение и отказоустойчивость

При запуске приложение один раз читает сериализованное доменное состояние из `localStorage`. Адаптер оборачивает чтение, JSON-парсинг и проверку формы данных в безопасную обработку: отсутствующие, повреждённые или несовместимые данные превращаются в пустое состояние. После успешных изменений Redux сериализует только цели и операции обратно в хранилище.

Ошибка доступа или записи в `localStorage` не должна прерывать сессию: приложение продолжает работать с текущим состоянием памяти. Производные значения никогда не сохраняются в хранилище.

## Ошибки и обратная связь

Формы показывают русскоязычные сообщения рядом с проблемным полем и не создают невалидные сущности. Нельзя отправить пустое название, нулевую, отрицательную или дробную сумму, а также снять сумму выше доступного баланса. Удаление требует явного подтверждения в модальном окне.

## Визуальная система

Базовый шрифт — Manrope с системным `sans-serif` fallback. Интерфейс использует SCSS со стилями рядом с компонентами, где это практично. Карточки не содержат кнопок операций; плотность элементов уменьшается на мобильных экранах без потери доступности и читабельности.

## Проверка качества

Автоматическими тестами покрываются:

- CRUD целей;
- добавление и удаление пополнений и снятий;
- отказ снятия при недостаточном балансе;
- каскадное удаление операций при удалении цели;
- вычисление баланса и ограничение прогресса;
- валидация положительных целых сумм;
- восстановление после повреждённого `localStorage`.

Перед завершением реализации выполняются тесты, линтер и production-сборка. Также проверяется прямое открытие обоих маршрутов и базовая адаптивность интерфейса на мобильной и широкой ширине.

## Зависимости

К стартовому CRA-проекту добавляются `@reduxjs/toolkit`, `react-redux` и `react-router-dom`. Существующий `sass` используется для SCSS. Реализация последовательно использует TypeScript, включая входной файл приложения.
